# hy2tun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a HY2-based reverse tunnel with FRP-style client-requested TCP/UDP port mappings, standard HY2 proxy compatibility, and server/client web management.

**Architecture:** Two Go binaries (`hy2tund`, `hy2tun`) share internal packages. The server wraps the official Hysteria 2 core with a custom `Outbound`; reverse TCP uses one HY2 stream per public connection claimed by a one-time token, reverse UDP uses HY2 native datagrams with the public peer address as the session tag. Client config is authoritative; server web pushes changes with revision checks.

**Tech Stack:** Go 1.26, `github.com/apernet/hysteria/core/v2 v2.13.0`, `github.com/apernet/hysteria/extras/v2 v2.13.0`, `gopkg.in/yaml.v3`, `log/slog`, `html/template`, `embed`, SSE, `golang.org/x/crypto/bcrypt`.

**Spec:** `/root/opencode-task/docs/superpowers/specs/2026-10-27-hy2-reverse-tunnel-design.md`

## Global Constraints

- Project root: `/root/opencode-task/hy2tun` (new independent git repo). All paths below are relative to it.
- Module path: `hy2tun`. Go 1.26 toolchain, `GOTOOLCHAIN=auto`.
- Pin `core/v2 v2.13.0` and `extras/v2 v2.13.0`. Do not fork or copy Hysteria source; use public APIs only.
- Release builds: `CGO_ENABLED=0`, `-trimpath -ldflags "-s -w"`.
- Config files are written atomically (temp file → fsync → rename) with mode 0600; keep one `.bak`.
- Never log passwords, control tokens, UDP tokens, private keys, or full config dumps.
- Web assets are embedded with `embed.FS`; no CDN, no Node build step.
- All tests run with `go test ./...`; concurrency-sensitive packages also run with `go test -race ./...`.
- Commit after every task with a conventional commit message.
- Protocol constants, virtual address prefixes, error codes, and revision rules are fixed by the spec. Changing one requires updating the spec first.

## Review Focus

These are the five failure modes most likely to bite a user; each has a test in the task that owns the code.

1. **Hostile control frames** — oversized length prefix, truncated body, malformed JSON, unknown type. The stream must close; the process must stay alive. Test in Task 3.
2. **Port race between two clients** — simultaneous registration for the same port. Exactly one wins, the other gets `port_in_use`; no double bind or leaked listener. Test in Task 6.
3. **UDP datagrams near the HY2 size limit** — 1200-byte and 4096-byte payloads must not panic; they either arrive intact or are dropped with a log. Test in Task 8.
4. **Client reconnect with a lower revision** (restored config) — server adopts the client's revision instead of forcing a conflict. Test in Task 9.
5. **Deleting a mapping with active connections** — public connections close, the port frees, and no goroutine keeps running. Test in Task 7 (TCP) and Task 8 (UDP).

- [ ] **Step 7: Implement push transaction**

`PushMappings`:

1. Find the online session; if missing, return `control.ErrClientOffline`.
2. Lock the per-client control queue.
3. If `baseRevision != session.revision`, return `control.ErrConflict`.
4. Pre-bind only mappings whose **protocol or port** changed or that are new. A `local_addr` or `note` change keeps the existing listener; a `local_addr` change closes active connections and updates the mapping metadata. A type change closes the old listener and binds the new one. On any pre-bind failure, close newly bound listeners and return a `PushError` with per-mapping results.
5. Send `Push{BaseRevision: base, Revision: base+1, Mappings: effective}` where `effective` has assigned ports filled in for `remote_port: 0`.
6. Wait for `PushAck` with a 10-second timeout.
7. On success: commit (close removed mappings and active conns), update session/state, return new revision.
8. On conflict: rollback pre-bound listeners, return `control.ErrConflict`.
9. On timeout: rollback pre-bound listeners, return `control.ErrPushTimeout`.

Client `handlePush`:

1. If `msg.BaseRevision != c.revision`, send `PushAck{OK:false, Error:"conflict", Revision:c.revision}`.
2. Apply the new mapping list in memory, set `revision = msg.Revision`.
3. Write config atomically. On failure, roll back and send `PushAck{OK:false, Error:"write_failed"}`.
4. Send `PushAck{OK:true, Revision:msg.Revision, Results:...}`.
5. Reconcile UDP sessions: start/stop sessions for added/removed/changed mappings.
